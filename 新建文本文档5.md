LAYER 3 — 长期：Relation-Internalized ObjectFile / General SVT Benchmark
============================================================

目标：
把当前 ObjectFile 线提升成更一般的“关系内化结构有效性测试”框架。

新增规划文档：
reports/Long_Term_Relation_Internalized_SVT.md

必须说明：

1. 总框架
   SVT = 结构声称判别器
   ObjectFile = 第一个最小结构样本
   Relation Internalization = 解释结构如何从外部关系变成内部可更新、可裁决、可迁移机制

2. 当前 ObjectFile 中已经存在的关系
   - feature-identity relation
   - trajectory-continuity relation
   - occlusion-persistence relation
   - conflict-resolution relation
   - confidence relation

3. 下一阶段 Relation-Specific ObjectFile
   每种 relation 都有：
   - state
   - uncertainty
   - update rule
   - inspection trigger
   - failure mode

4. Relation-specific inspection
   区分：
   - feature uncertainty
   - trajectory uncertainty
   - occlusion uncertainty
   - conflict uncertainty

   不做 blanket inspection。
   应设计：
   - NoInspectionObjectFile
   - BlanketInspectionObjectFile
   - RelationSpecificInspectionObjectFile
   - OracleInspectionObjectFile

5. General SVT benchmark
   未来不只测试 object identity，还可以测试：
   - relation reasoning
   - causal intervention
   - tool-use relation
   - graph structure
   - latent reasoning tokens
   - communication/emergent symbols

6. 核心原则
   对任何结构声称，都问：
   - 是否超过强记忆基线？
   - 打乱结构内容是否性能下降？
   - 容量受限时是否比记忆更稳？
   - 错误先验能否被反馈推翻？
   - 置信度是否对应效用？
   - 是否能在 OOD / conflict / intervention 下保持功能？

输出：
- reports/Long_Term_Relation_Internalized_SVT.md

不要：
- 不要实现长期模型
- 不要新增实验
- 只写规划和理论连接
